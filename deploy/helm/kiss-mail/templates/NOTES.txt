5. Admin account:

   An "admin" superadmin account is created on first start. Its generated
   password is written to /data/initial-admin-password (it is not logged):
   kubectl exec deploy/{{ include "kiss-mail.fullname" . }} -n {{ .Release.Namespace }} -- cat /data/initial-admin-password

   It must be changed at first login. Easiest: log in to the web admin with
   it (port-forward above) and set a new one when prompted.
{{- if eq (include "kiss-mail.secureCookie" .) "true" }}
   (KISS_MAIL_WEB_SECURE_COOKIE=true: log in over https, not the port-forward.)
{{- end }}

   Or from the command line (the password is read from stdin, so it stays
   out of the process list). The running server keeps accounts in memory, so
   restart it right away so it reloads users.json:
   read -rs P   # type the new password
   printf '%s' "$P" | kubectl exec -i deploy/{{ include "kiss-mail.fullname" . }} -n {{ .Release.Namespace }} -- kiss-mail passwd admin --stdin
   kubectl exec deploy/{{ include "kiss-mail.fullname" . }} -n {{ .Release.Namespace }} -- rm -f /data/initial-admin-password
   kubectl rollout restart deploy/{{ include "kiss-mail.fullname" . }} -n {{ .Release.Namespace }}

6. Quick CLI commands (restart the deployment after changes, see above):

   # List users
   kubectl exec -it deploy/{{ include "kiss-mail.fullname" . }} -n {{ .Release.Namespace }} -- kiss-mail list

   # Add user
   kubectl exec -it deploy/{{ include "kiss-mail.fullname" . }} -n {{ .Release.Namespace }} -- kiss-mail add <username> <password>

   # Check stats
   kubectl exec -it deploy/{{ include "kiss-mail.fullname" . }} -n {{ .Release.Namespace }} -- kiss-mail stats

7. TLS ({{ include "kiss-mail.tlsMode" . }}):
{{- if not (include "kiss-mail.tlsEnabled" .) }}

   tls.mode=off: no TLS listeners or STARTTLS, and plaintext logins are
   allowed. Passwords cross the network in the clear.
{{- else if .Values.tls.existingSecret }}

   Certificate: Secret {{ .Values.tls.existingSecret }}, mounted at
   /etc/kiss-mail/tls. Renewed certificates are picked up within 60 seconds.
{{- else }}

   No tls.existingSecret: the server uses /data/tls/cert.pem + key.pem if
   present, otherwise a self-signed certificate in /data/tls. Mail clients
   warn about it, and Outlook and Gmail refuse it. For a real certificate,
   create a kubernetes.io/tls Secret (e.g. a cert-manager Certificate) and
   set tls.existingSecret.
{{- end }}

   BREAKING (native TLS release) checklist:
   - Logins without TLS are now refused by default
     (tls.allowPlaintextAuth={{ .Values.tls.allowPlaintextAuth }}). Switch mail clients to
     IMAPS/SMTPS/POP3S or STARTTLS, or set tls.allowPlaintextAuth=true
     while you migrate them.
   - Expose the TLS ports: externalService.ports.smtps/imaps/pop3s
     (465/993/995) on the LoadBalancer, and allow them in any firewall or
     NetworkPolicy of your own (the chart's networkPolicy already does).
   - An expired certificate in tls.existingSecret stops the server from
     starting; keep the Secret renewed (cert-manager does this).
   - tls.mode=off restores the old behaviour (no TLS, plaintext logins).
